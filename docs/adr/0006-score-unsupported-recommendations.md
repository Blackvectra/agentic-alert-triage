# Recommendations are scored like claims, and none is warranted on benign or abstain cases

The assignment requires evaluating unsupported recommendations, but proposed actions were only passed to the approval gate and never scored. Each proposed action must now cite `evidence_ids` (`{"action": str, "evidence_ids": [str]}`), the same evidence link claims have. A recommendation is unsupported if it cites nothing, cites evidence not retrieved in that run, or is proposed at all on a case whose expected answer is benign or abstain, because acting on a benign or undecidable alert is the harm the approval gate exists to stop. The format change applies to every config's prompt; C enforces it (an action without evidence makes the output invalid, which counts as an abstention) and B keeps what it sent. It was made before any held-out run; the prompt fingerprint changed, so resume reruns earlier dry-run results automatically. Factual correctness is measured as a correct disposition plus claims citing retrieved evidence; the wording of claims and actions is not judged, consistent with the project's no-LLM-judge, fixed-rule scoring.
