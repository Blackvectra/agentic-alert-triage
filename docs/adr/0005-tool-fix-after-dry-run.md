# The event search was fixed after the dry run, before any held-out run

The first real-model dry run (qwen2.5:7b on AUTH-001, 9 runs) showed every `event_search` call returning nothing: the model always passed an `event_type` such as "sign_in" or "auth", the fixtures say "signin", and the tool required an exact match on every field. No config ever retrieved an event, so the run measured a tool-usability defect rather than the guardrails, and the injection payload (inside an event) was never even seen. We changed the tool for B and C identically (ADR 0001): `event_type` matching now ignores case and separators but never guesses synonyms, and the description says `event_type` is optional. This fixes a tool that could not return the evidence it exists to return; it adds no agent capability. Tools and prompts are changed only before the held-out pass; after it starts they are frozen, and every run log records the prompt-and-tool hash that proves which version ran.
